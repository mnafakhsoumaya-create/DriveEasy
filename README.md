# DriveEasy Microservice Project\n\nThis repository implements the DriveEasy system exactly as specified in the provided PDF. No additional features have been added. All data is stored in‑memory.\n\n## Project Structure\n\n- `driveeasy-backend/` – Maven multi‑module root\n- `service-registry/` – Eureka service registry\n- `config-server/` – Spring Cloud Config Server (native profile pointing to `driveeasy-config/`)\n- `vehicule-service/` – Vehicle management microservice\n- `client-service/` – Client management microservice\n- `location-service/` – Rental / reservation microservice (includes loyalty logic)\n- `api-gateway/` – Spring Cloud Gateway exposing a unified API\n- `driveeasy-config/` – Configuration repository (YAML files used by Config Server)\n- `docker-compose.yml` – Docker compose file that currently runs Zipkin for tracing\n\n## Prerequisites\n\n- **Java JDK 21** (set `JAVA_HOME` accordingly)\n- **Maven 3.9+**\n- **Docker** (optional, for Zipkin)\n\n## Build\n\n```bash\ncd c:\\Users\\MSI\\Desktop\\DriveEasy\\driveeasy-backend\n#mvn clean install   # builds all modules\n```\n\nAll modules compile successfully (BUILD SUCCESS).\n\n## Running the Stack\n\nOpen separate terminals for each service (or use a terminal multiplexer). Execute the following commands in order:\n\n1. **Eureka Service Registry**\n```bash\ncd service-registry\nmvn spring-boot:run\n```\n\n2. **Config Server**\n```bash\ncd ..\\config-server\nmvn spring-boot:run\n```\n\n3. **Vehicle Service**\n```bash\ncd ..\\vehicule-service\nmvn spring-boot:run\n```\n\n4. **Client Service**\n```bash\ncd ..\\client-service\nmvn spring-boot:run\n```\n\n5. **Location Service**\n```bash\ncd ..\\location-service\nmvn spring-boot:run\n```\n\n6. **API Gateway**\n```bash\ncd ..\\api-gateway\nmvn spring-boot:run\n```\n\n7. **Zipkin (optional)** – start the tracing server via Docker Compose:\n```bash\ncd ..\\driveeasy-backend\ndocker compose -f docker-compose.yml up -d\n```\n\n## Verification\n\n- Open **Eureka Dashboard** at `http://localhost:8761/` – all services should be listed as UP.\n- Open **Config Server** at `http://localhost:8888/` – you can view the raw YAML files.\n- Use the **API Gateway** (`http://localhost:8080/api/...`) to call the endpoints defined in the PDF. Example curl commands:\n\n```bash\n# List vehicles\ncurl http://localhost:8080/api/vehicules\n\n# List clients\ncurl http://localhost:8080/api/clients\n\n# Create a reservation (Location)\ncurl -X POST http://localhost:8080/api/locations \\\n     -H "Content-Type: application/json" \\\n     -d '{"clientId":1,"vehicleId":1,"dateDebut":"2024-01-01","dateFin":"2024-01-05"}'\n```\n\nAll responses should match the behavior described in the PDF (e.g., duplicate checks, loyalty upgrades, penalty calculations, etc.).\n\n## Clean Up\n\nStop each Spring Boot application with `Ctrl+C` in its terminal. If you started Zipkin, stop it with:\n```bash\ndocker compose -f docker-compose.yml down\n```\n\n---\n\nThe project is now ready for use. No extra files or functionality have been added beyond the specification.\n
